fix(hotel): rewrite hotel search pipeline for correctness and reliability

Root-caused and fixed a chain of bugs that caused hotel search to miss
in-budget hotels, ignore star-rating filters, and occasionally return
invalid/garbled JSON output.

- tools/search_hotels_full.py (new): deterministic wrapper around the
  Vio search_hotels MCP tool.
  - Paginates through ALL result pages (nextOffsets + hasMoreResults)
    instead of relying on the LLM to decide when to paginate.
  - Requests prices explicitly in TRY (currency param) so the user's
    budget is compared with zero currency conversion.
  - Reads price from offers.cheapestRate.displayPrice (falls back to
    base+taxes+hotelFees), matching Vio's real response shape.
  - Filters by budget and min_star_rating locally in Python, and
    excludes isPartialMatch hotels from hotels_in_budget so partial
    upstream matches never pass as "within budget".
  - Scopes "already shown" hotel de-duplication to a search-specific
    key (destination+dates+travelers+area+stars) so switching search
    criteria doesn't wrongly suppress previously-seen hotels.
  - Uses roomsConfiguration (not rooms) and prefers structuredContent
    over manual content[0].text JSON parsing, matching verified live
    API behavior.

- agents/hotel_agent.py: use search_hotels_full instead of letting the
  LLM call the raw search_hotels tool directly.
  - Makes min_star_rating extraction from the user's message mandatory
    with explicit trigger-phrase examples, fixing star filters being
    silently ignored (min_star_rating=null even when e.g. "en az 5
    yildizli" was requested).
  - Removes a stale "convert budget to EUR" instruction that
    contradicted the wrapper's TRY-only contract.
  - Adds explicit anti-hallucination rules for price/amenity/rating
    fields and a rule to keep nightly_price null when total_price is
    null instead of estimating it.

- agent_runner.py: retry once on structured-output validation errors,
  and retry with backoff (honoring Google's suggested retryDelay) on
  429 RESOURCE_EXHAUSTED quota errors before surfacing a clean error
  instead of a raw traceback.
